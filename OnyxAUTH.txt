OnyxAUTH — Agent Reference
==========================

## What this is
Centralized auth service for the Onyx platform. Deployed at auth.onyxpowered.com.
All Onyx apps live on subdomains of onyxpowered.com, sharing a single session cookie.
Built on Next.js 16 + Better Auth 1.6 + Postgres + shadcn/ui (Vercel dark theme).

## Stack
- Framework: Next.js 16 (breaking changes — middleware is proxy.ts with named export `proxy`, cookies()/headers() must be awaited)
- Auth: Better Auth 1.6 (plugins: onyx pass, nextCookies)
- DB: Postgres via pg Pool
- UI: shadcn/ui v4 (radix/lyra preset — rounded-none patched to rounded-md/xl, overflow-hidden removed from Card)
- Styling: Vercel dark — pure black bg, Geist Sans, white primary, white focus rings
- App name: configured via NEXT_PUBLIC_APP_NAME env var, defaults to "Zero" (src/lib/config.ts)

## Auth methods
1. Email + password (Better Auth built-in)
2. Google OAuth (credentials in .env.local — GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET)
3. GitHub OAuth (credentials in .env.local — GITHUB_CLIENT_ID / GITHUB_CLIENT_SECRET)
4. Onyx Pass — server-managed Ed25519 keypair, client holds only a rotating device token
   - Token stored in localStorage under key "onyx.pass.v2"
   - POST /onyx/create-pass  (requires session) — generates keypair, returns { deviceToken, publicKey }
   - POST /onyx/auth { deviceToken } — looks up record, creates session, rotates token, returns { deviceToken }
   - Private key never leaves the server; encrypted at rest with AES-256-GCM (PASS_ENCRYPTION_KEY)
   - Server plugin: src/lib/onyx/plugin.ts
   - Client plugin: src/lib/onyx/client.ts
   - Client helpers: src/lib/onyx/identity.ts (getDeviceToken, saveDeviceToken, clearDeviceToken, hasPass)

## Cross-subdomain session
Session cookie is set with domain=COOKIE_DOMAIN (e.g. .onyxpowered.com).
All *.onyxpowered.com apps share the cookie automatically — no token handoff needed.
Calling apps validate sessions server-side via Better Auth's auth.api.getSession().

## Routing a user to auth from a calling app
Link to:
  https://auth.onyxpowered.com/login?redirectTo=https://zero.onyxpowered.com/dashboard
  https://auth.onyxpowered.com/signup?redirectTo=https://zero.onyxpowered.com/dashboard

After auth, user is redirected to redirectTo. Only *.onyxpowered.com destinations are
accepted (validated in src/lib/redirect.ts) — anything else falls back to /account.
The redirectTo param is preserved across login↔signup navigation and through Pass flow.

## Post-signup Pass flow
After email signup, user sees SavePassPrompt. "Save Pass" calls POST /onyx/create-pass,
saves the returned deviceToken to localStorage. "Skip" goes straight to redirectTo.

## Onyx Pass — security notes
- PASS_ENCRYPTION_KEY must be rotated before production (dev key is committed)
- /onyx/auth endpoint needs rate limiting before production
- redirectTo is validated client-side in safeRedirectTo(); add server-side check for defense in depth
- Device token rotates on every auth — stale tokens are immediately invalidated
